# 弱网测试方案

> 版本: v1.0 | 日期: 2026-08-07 | 适用框架: mobile-test-framework

## 一、功能分层

弱网测试分为两个层级:

| 层级 | 能力 | 实现 | 适用 |
|---|---|---|---|
| **开关级** | 断网 / 仅WiFi / 仅移动数据 / 飞行模式 | ADB `svc`/`settings` 命令,已实现 | 断网场景:离线提示、暂存、错误态 |
| **限速级** | 带宽限制 / 丢包 / 延迟模拟 | PC侧代理(mitmproxy/Charles),**接口已预留** | 真正的弱网场景:慢加载、超时重试 |

> **真机弱网限速必须走 PC 侧代理**:手机 WiFi 代理指向 PC,
> 流量经 PC 代理转发并限速。这是业界标准做法(模拟器可用 `network speed` 命令,真机不行)。

## 二、开关级断网(已实现)

### 网络模式

```python
from utils.network_controller import NetworkController

net = NetworkController()
net.set_mode("offline")       # 完全断网 (关WiFi+移动数据)
net.set_mode("airplane")      # 飞行模式
net.set_mode("wifi_only")     # 仅WiFi
net.set_mode("mobile_only")   # 仅移动数据
net.set_mode("normal")        # 恢复全部网络
net.is_offline()              # 连通性探测 (ping 8.8.8.8)
net.check_connectivity()      # 综合状态 {"offline","wifi","mobile_data","airplane"}
```

### 配置

```yaml
network:
  weaknet_mode: "offline"     # 默认弱网模式
  throttle:                   # 限速配置 (预留)
    backend: "none"           # none / mitmproxy / charles
    down_kbps: 100
    up_kbps: 50
    latency_ms: 500
    proxy_host: "127.0.0.1"
    proxy_port: 8899
```

### 自动化用例

```bash
python run_tests.py --module network
```

对应测试:`tests/test_network.py`(5个用例,标记 `@pytest.mark.weaknet`):

| 用例 | 验证点 |
|---|---|
| test_disconnect_all_blocks_network | 断网后网络不可用 |
| test_restore_network_recovers | 断网→恢复→网络可用 |
| test_airplane_mode | 飞行模式生效与恢复 |
| test_login_fails_when_offline | 断网登录错误态(不崩溃) |
| test_throttle_interface_reserved | 限速接口协议完整(永远通过) |

**`weak_network` fixture 保证用例 teardown 强制恢复网络,不污染后续用例。**

## 三、限速级弱网(接口预留)

### 当前状态

`ThrottleController` 抽象协议已定义,默认返回 `NullThrottleController`
(available()=False,调用 apply() 仅 WARN 提示)。

### 接入步骤(以 mitmproxy 为例)

#### 1. PC 安装 mitmproxy

```bash
pip install mitmproxy
```

#### 2. 编写限速脚本 `throttle.py`

```python
# 简单的带宽/延迟模拟 (mitmproxy addon)
import time

class Throttle:
    def __init__(self):
        self.down_kbps = 100   # 下行限速
        self.latency_ms = 500  # 延迟

    def request(self, flow):
        time.sleep(self.latency_ms / 1000)

    def response(self, flow):
        # 实际带宽限速建议用 mitmproxy 的 bandwidth 插件或 tc 命令
        pass

addons = [Throttle()]
```

#### 3. PC 启动代理

```bash
mitmproxy -s throttle.py --listen-port 8899
```

#### 4. 手机 WiFi 代理指向 PC

手机连接与 PC 同一 WiFi → 设置代理为 `PC的IP:8899`
(也可用 `adb shell settings put global http_proxy PC_IP:8899` 设置)

#### 5. 实现 ThrottleController 后端

在 `utils/network_controller.py` 中注册:

```python
class MitmproxyThrottleController(ThrottleController):
    @property
    def name(self): return "mitmproxy"

    def available(self):
        # 检查 PC 上 mitmproxy 端口是否可达
        import socket
        try:
            socket.create_connection(("127.0.0.1", 8899), timeout=2).close()
            return True
        except OSError:
            return False

    def apply(self, down_kbps, up_kbps, latency_ms):
        # 通过 mitmproxy API/配置更新限速参数
        ...

    def remove(self):
        ...
```

在 `get_throttle_controller()` 中按 `config.network.throttle.backend` 返回对应实现。

#### 6. 使用

```python
net = NetworkController()
controller = net.get_throttle_controller()
if controller.available():
    controller.apply(down_kbps=100, up_kbps=50, latency_ms=500)
    # ... 执行弱网场景测试 ...
    controller.remove()
```

### Charles 替代方案

Charles 的 **Throttle Settings** 内置限速配置,设备代理指向 PC:8888 即可,
无需写脚本;框架侧同样通过 `ThrottleController` 接口集成。

## 四、注意事项

1. **必须恢复网络**:断网用例 teardown 强制 `restore_all()`,
   手动测试也务必恢复,否则影响其他操作
2. **小米 HyperOS 兼容**:`svc wifi disable` 在部分版本失效,
   框架已自动回退 `cmd wifi set-wifi-enabled disabled`
3. **限速粒度**:代理方案针对 HTTP/HTTPS 流量;
   非代理流量(如部分原生TCP)需用 `tc` 命令(需要 root)
4. **电量/性能干扰**:弱网测试时注意手机电量和网络信号本身的变化,
   性能类断言建议在正常网络下单独执行
5. **模拟器弱网**:模拟器可用 `emulator -netdelay gprs -netspeed gsm`
   启动参数,或 `telnet localhost 5554` 后 `network speed` 命令
