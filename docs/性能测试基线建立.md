# 性能测试基线建立

> 版本: v1.0 | 日期: 2026-08-07 | 适用框架: mobile-test-framework

## 一、功能概述

框架提供完整的性能采集能力:

| 指标 | 采集方式 | 说明 |
|---|---|---|
| 冷启动耗时 | `am start -W` TotalTime | force-stop 后启动,Android 12+ 自动识别 COLD |
| 热启动耗时 | `am start -W` TotalTime | HOME切后台后启动,自动识别 WARM |
| CPU占用 | `top -b -n 1`(按表头定位%CPU列) | 回退 `dumpsys cpuinfo` |
| 内存 | `dumpsys meminfo` TOTAL PSS | Android 8+ 新格式,旧格式自动回退 |
| 电量 | `dumpsys battery` | level/status/temperature;uiautomator2 driver 无电量API,必须走ADB |
| 页面响应时间 | 测试代码 `pc.timer()` 计时 | 上下文管理器,自动校验阈值 |

**采集全部走 ADB 层,不依赖 driver,browser/native 双模式可用。**

## 二、阈值策略

```yaml
performance:
  threshold_policy: "warn_only"   # warn_only: 超阈值仅提示 / strict: 超阈值判失败
  thresholds:
    cold_start_ms: 5000           # 冷启动耗时
    warm_start_ms: 2000           # 热启动耗时
    operation_response_ms: 3000   # 页面操作响应时间
    memory_mb: 500                # TOTAL PSS 内存
    cpu_percent: 80               # 单次采样 %CPU
    battery_drop_percent: 5       # 单用例电量下降
```

- **warn_only(默认)**:超阈值仅 WARN + Allure 展示,**不失败**——先建基线
- **strict**:超阈值用例失败——基线建立后用于回归
- 命令行覆盖:`--perf-baseline`(强制只采集不告警)/ `--perf-strict`(强制严格模式)

## 三、建立基线流程(APK 就绪后)

### 第 1 步:确保环境稳定

```bash
# 1. 连接设备并确认可用
adb devices

# 2. 手机打开"开发者选项"关闭动画 (减少动画对启动耗时影响)
#    设置 → 开发者选项 → 关闭 窗口动画缩放/过渡动画缩放/动画程序时长缩放

# 3. 屏幕保持常亮,连接充电(避免电量策略干扰)
```

### 第 2 步:运行基线采集(3次取中位)

```bash
python run_tests.py --module performance --perf-baseline
# 第1次运行 (预热/校准)
# 第2次运行
# 第3次运行
```

每次运行生成 `reports/performance/perf_YYYYMMDD_HHMMSS.csv`,
包含冷启动/热启动/内存/CPU 原始数据。

### 第 3 步:统计中位数并回填配置

用 Excel 打开 CSV(utf-8-sig 编码,不会乱码),对每项指标取 3 次运行的中位数:

| 指标 | 3次中位数 | 建议阈值(×1.3~1.5余量) |
|---|---|---|
| cold_start_ms | 2500 | 3500~4000 |
| warm_start_ms | 800 | 1200 |
| operation_response_ms | 1500 | 2200 |
| memory_mb | 280 | 400 |
| cpu_percent | 45 | 80 |

将建议阈值回填到 `config.yaml` 的 `performance.thresholds`。

### 第 4 步:切换严格模式(可选)

基线稳定后,在 CI 或日常回归中启用严格模式:

```bash
python run_tests.py --module performance --perf-strict
```

或修改 `config.yaml`:`threshold_policy: "strict"`

## 四、测试用例说明

`tests/test_performance.py`(8个用例,标记 `@pytest.mark.perf`):

| 用例 | 验证点 |
|---|---|
| test_cpu_snapshot | CPU快照格式合法 |
| test_memory_snapshot | 内存TOTAL PSS可读 |
| test_battery_snapshot | 电量0-100,状态可读 |
| test_startup_cold_with_threshold | 3轮冷启动 + 阈值校验 + CSV写入 |
| test_page_operation_response | timer计时页面操作 |
| test_sampling_during_scenario | 场景定时采样(≥3样本) |
| test_threshold_policy_warn_only | 阈值策略行为 |
| test_csv_encoding_utf8_sig | CSV带BOM(Excel兼容) |

**目标App未安装时自动回退 Chrome(com.android.chrome)验证采集机制**,
APK就绪后自动切换为目标App。

## 五、采样与报告

- **定时采样**:`pc.start_sampling(pkg)` 启动 daemon 线程按 `sample_interval`(默认2s)
  采样 CPU/内存/电量,`pc.stop_sampling()` 停止并计算均值/峰值,
  自动 attach Allure + 写CSV
- **操作计时**:`with pc.timer("登录流程"): ...` 上下文管理器
- **报告输出**:
  - CSV:`reports/performance/perf_*.csv`(utf-8-sig,Excel可开)
  - Allure:采样摘要 + 启动统计 + 阈值结果

## 六、注意事项

1. **性能数据不可重跑**:所有 perf 用例带 `@pytest.mark.flaky(reruns=0)`,
   重跑会污染数据
2. **CPU瞬时抖动大**:单次快照仅参考,统计取多次中位数
3. **电量注意**:`dumpsys battery` 是只读服务;若其他工具执行过
   `dumpsys battery set level N`(测试态),必须先 `dumpsys battery reset`
4. **基线环境**:建立基线与后续对比应在相同设备/系统版本/网络条件下进行
5. **阈值默认值只是起点**:首次基线后按真机实际校准
