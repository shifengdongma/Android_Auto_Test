## 一、项目背景

低空空管自动化系统正在从 PC Web 端向移动端扩展。移动端第一迭代包含五大模块：登录、首页（消息通知 + AI 问答）、申报（地图 + GPS + 飞行计划）、资讯、我的。当前阶段尚无正式 APK，采用手机 Chrome 浏览器访问 H5 页面进行测试。

### 2.3 核心架构特性

1. **双模式支持**：配置文件 `test_mode` 一键切换 browser 模式（H5 测试）和 native 模式（APK 测试）
2. **Page Object Model**：四层架构（测试用例 → Page Object → Driver → 基础设施），页面变更只需修改 Page 类
3. **自动设备适配**：通过 ADB 自动检测设备 Android 版本，修正配置中的版本号
4. **失败自动诊断**：失败截图 + 页面源码自动附加到 Allure 报告
5. **环境自检**：`setup_check.py` 一键检查 10 项环境前提条件

## 三、解决的关键技术问题

### 3.1 Appium 3.6 + Android 16 + Chrome 150 兼容链

这是本次工作中遇到的最大挑战。三个组件都是较新版本，存在多个兼容性问题：

```
Appium 3.6.0
    ├── ANDROID_HOME 环境变量 → 设置系统环境变量 + 代码自动检测
    ├── platformVersion 写死 → ADB 自动检测修正
    ├── hidden_api_policy 权限 → --relaxed-security 绕过
    ├── language/locale 拼接错误 → 移除配置项
    └── --allow-insecure 格式变更 → 改用 --relaxed-security

UiAutomator2 8.2.2
    └── skipDeviceInitialization 不生效 → set_capability 直接注入

Chrome 150.0.7871
    └── ChromeDriver 映射表缺失 → 手动下载 150.0.7871.124
```

### 3.2 浏览器模式 vs 原生模式的架构设计

两个模式共用同一套 Page Object 接口，底层由 `AppiumDriverManager` 根据 `test_mode` 配置自动选择：

- **browser 模式**：`browserName: Chrome` + ChromeDriver → CSS Selector / XPath 定位
- **native 模式**：`appPackage` + `appActivity` + UiAutomator2 → resource-id / UiSelector 定位

### 7.3 关键架构决策

1. **ADB 层核心**：性能/生命周期/APK 能力全部走 ADB，不依赖 driver —— 双模式兼容、
   driver 挂掉后仍能采集
2. **守卫机制**：`require_apk`/`require_native_mode` 用 skip 而非 fail ——
   APK 未就绪时仓库保持全绿
3. **弱网分层**：开关级断网已实现；限速通过 `ThrottleController` 协议预留
   （真机弱网限速必须 PC 侧代理，接入步骤已写入文档）
4. **性能基线流程**：warn_only 默认不失败 → `--perf-baseline` 跑 3 次取中位
   → 回填 config 阈值 → `--perf-strict` 严格回归

### 7.4 下一步（正式 APK 就绪后）

1. APK 放入 `apk/` 目录 → `--module install` 自动安装/升级
2. `test_mode` 切换 native，Appium Inspector 校准定位器
3. 建立性能基线（冷启动/热启动/内存），回填阈值后启用严格模式

## 八、第三阶段：多设备支持（2026-08-11）

### 8.1 背景

测试设备从 Redmi K80 (Android 16) 更换为华为 NOH-AN01 (Android 12)。启动时出现
`The instrumentation process cannot be initialized` 错误。经过系统调试定位两个根因：
(1) `skipServerInstallation: true` 导致华为首次使用缺少 Appium 辅助 APK；
(2) 被测应用 `com.dolphin.atc` 未安装在华为设备上。

### 8.2 新增能力

| 能力 | 实现 | 说明 |
|------|------|------|
| 多设备配置 | 3 个独立设备条目（Redmi K80 / Huawei NOH-AN01 / Emulator Pixel6） | 每个设备有独立的 platformVersion、skipServerInstallation 等配置 |
| 自动设备匹配 | UDID→Model→回退 三级匹配 | 插上哪台设备自动选对应配置，无需手动设 DEVICE_INDEX |
| 预检查机制 | `_ensure_app_installed()` | 会话创建前确认应用已安装，未安装时自动从本地 APK 安装 |
| APK 跨设备迁移 | `ADBHelper.extract_apk()` | 从旧设备提取 APK 安装到新设备 |

### 8.3 新增/修改文件

| 文件 | 变更 | 说明 |
|------|------|------|
| `config/config.yaml` | 新增 1 条设备配置 | 华为 NOH-AN01（Android 12, skipServerInstallation=false） |
| `config/config_manager.py` | +2 方法 | `get_device_config_by_model()` / `get_device_config_by_udid()` |
| `drivers/appium_driver.py` | +3 方法 | `_auto_match_device()` / `_find_device_index()` / `_ensure_app_installed()` |
| `utils/adb_helper.py` | +1 方法 | `extract_apk()` — 从设备提取 APK 文件 |

### 8.4 关键设计原则

1. **不破坏原有配置**：Redmi K80 配置完全不变，新设备独立条目
2. **插上即用**：自动检测设备型号匹配配置，零配置切换
3. **友好错误提示**：应用未安装时给出 4 种解决路径
4. **渐进验证**：先用百度验证华为设备可正常创建 Appium Session，再切回目标应用

### 8.5 设备配置差异

| 配置项 | Redmi K80 | Huawei NOH-AN01 | 原因 |
|--------|-----------|-----------------|------|
| platform_version | 16 | 12 | 设备实际 Android 版本不同 |
| skip_device_initialization | true | false | 华为 Android 12 需要标准初始化流程 |
| skip_server_installation | true | false | 华为首次使用需安装 Appium 辅助 APK |

### 10.3 关键技术问题

**0. 空域绘制手势（留空飞行）**

uni-app 地图画布无 a11y 元素，三种空域绘制全部通过坐标手势实现（真机实测验证）：

| 空域类型 | 手势 | 实现 |
|---------|------|------|
| 多边形 | 单击加点，双击结束 | `driver.tap` × N + `mobile: doubleClickGesture` |
| 圆形 | 长按后向外拖动 | `mobile: dragGesture`（duration=1500 慢速拖动模拟长按） |
| 线缓冲区 | 单击加点，双击结束 | 同多边形 |

注意点：输入空域名称后**必须关闭输入法键盘**，否则底部"修改/下一步"按钮被键盘遮挡不可见。

**1. WebView a11y 树不确定性（最大挑战）**

uni-app 页面内容渲染在 WebView，a11y 树构建延迟且随页面状态变化：
- 内容区 a11y 树在页面被单次点击后约 4 秒构建完成，反复点击会打断构建
- 树中同时包含后台堆叠页面节点，同文案节点必须用 `is_displayed` + 位置区间过滤
- 表单值节点可能延迟进入树 → 重试前先做"已选中"确认，避免误判失败

**2. 子串误判类 Bug（两次）**

| 场景 | 误判 | 修复 |
|------|------|------|
| 选择列表结果项 | 首页卡片"新疆起降场1 → 新疆起降场2"textContains 命中 | 结果项改精确匹配 |
| 备降地字段校验 | 相邻降落地字段同值"新疆起降场2"命中 | 校验限定字段行区间 |

**3. 设备端仪器进程死锁**

强杀会话导致 `io.appium.uiautomator2.server` 进入 D 状态（内核级死锁），所有元素查询
240s 超时无响应，表现为"设备无反应、测试卡在登录页"。强停/卸载 APK 均无效，
重启设备后恢复。教训：会话清理必须走正常退出流程。
