# 低空空管自动化系统 — 移动端测试总体方案

> 版本：v2.0  
> 更新日期：2026-08-04  
> 适用范围：移动端第一迭代（Android APP / H5）

---

## 一、项目背景

低空空管自动化系统正在从 PC Web 端向移动端扩展。移动端第一迭代包含**五大功能模块**：

| 模块 | 核心功能 | 移动端依赖 |
|------|---------|-----------|
| 登录 | 账号密码登录、找回密码、验证码 | — |
| 首页 | 消息通知（审批/告警/协调）、AI 智能问答、对话历史 | — |
| 申报 | 地图、GPS 定位、飞行计划创建、审批进度查询 | GPS、地图 SDK、文件上传、离线存储 |
| 资讯 | 法律法规、通知公告、系统公告 | — |
| 我的 | 信誉统计、关于我们、退出登录 | — |

当前阶段尚无正式 APK，移动端通过手机 Chrome 浏览器访问 H5 页面进行测试。待 APK 就绪后，框架可无缝切换至原生 APP 测试模式。

## 二、技术方案

```

│                   测试用例层                       │
│          Pytest 9.x  +  Allure 2.x               │

│     BasePage → LoginPage/HomePage/FlightPage/... │
├──────────────────────────────────────────────────┤
│                   驱动层                          │

├──────────────────────────────────────────────────┤

├──────────────────────────────────────────────────┤

└──────────────────────────────────────────────────┘
```

| 组件 | 版本 | 用途 |
|------|------|------|
| Python | 3.13 | 编程语言与测试逻辑 |
| Appium | 3.6.0 | 移动端自动化驱动服务 |
| Appium UiAutomator2 | 8.2.2 | Android 设备自动化引擎 |
| Pytest | 9.1.1 | 测试框架，用例编排与执行 |
| Allure | 2.16.0 | 可视化测试报告 |
| PyYAML | 6.0 | 配置与测试数据管理 |
| Selenium | 4.46.0 | Web 元素交互（浏览器模式） |

| ADB | 37.0.1 | Android 设备通信与调试 |
| Node.js | 24.18.0 | Appium 运行时环境 |

### 2.2 架构设计

采用 **四层 Page Object Model (POM)** 架构：

```
tests/                      ← 测试用例（断言 + 业务流程）
    │
pages/                      ← Page Object（元素定位 + 页面操作）
    │
drivers/                    ← Driver 管理（Session 生命周期）
    │
utils/ + config/            ← 基础设施（配置/日志/截图/ADB）
```

**核心设计模式：**

| 模式 | 应用位置 | 说明 |
|------|---------|------|
| Page Object | `pages/` | 每个页面封装为独立类，定位器与操作分离 |
| 单例 | `ConfigManager` | 全局唯一配置实例 |
| 工厂 | `AppiumDriverManager` | 根据平台/模式创建对应 Driver |
| 策略 | `config.yaml` | 通过配置切换 native/browser 模式 |

### 2.3 双模式支持

框架支持两种测试模式，通过 `config/config.yaml` 中的 `test_mode` 一键切换：

| 模式 | test_mode | 适用场景 | 底层引擎 |
|------|-----------|---------|---------|
| 浏览器模式 | `browser` | 测试移动端 H5 页面（当前阶段） | Chrome + ChromeDriver |
| 原生模式 | `native` | 测试原生 APK | UiAutomator2 + appPackage |

**浏览器模式工作流程：**

```
Python Client ──HTTP──► Appium Server :4723
                            │
                   ┌────────▼────────┐
                   │ UiAutomator2    │
                   │ Driver          │
                   └────────┬────────┘
                            │ 启动 Chrome
                   ┌────────▼────────┐
                   │ Chrome on       │
                   │ Android Device  │
                   └────────┬────────┘
                            │ ChromeDriver
                   ┌────────▼────────┐
                   │ H5 Page         │
                   │ (test URL)      │
                   └─────────────────┘
```

### 2.4 技术方案优缺点

#### 优点

1. **一套代码双端复用**：同一套 Page Object 和测试用例，切换 `test_mode` 即可适配浏览器模式和原生 APP 模式
2. **真实设备测试**：在真实 Android 手机上运行，覆盖真机特有的硬件交互（GPS、相机、传感器）
3. **强大的元素定位**：浏览器模式使用 CSS Selector / XPath，原生模式使用 resource-id / UiSelector，灵活适配
4. **失败自动诊断**：每次失败自动截图 + 保存页面源码到 Allure 报告，故障排查效率高
5. **数据驱动**：测试数据通过 YAML 管理，非技术人员也可维护
6. **渐进式交付**：当前无 APK 阶段可测 H5 页面，APK 就绪后无缝切换
7. **可扩展性**：架构预留 iOS (XCUITest) 扩展接口，BasePage 平台无关

#### 缺点

1. **Chrome 版本强依赖**：手机 Chrome 必须与 ChromeDriver 版本匹配，大版本升级后需手动更新 ChromeDriver
2. **Appium 启动开销**：每次创建 Session 约 5-10 秒（启动 Chrome + ChromeDriver 连接）
3. **H5 vs 原生差异**：浏览器模式下无法测试原生权限弹窗（GPS 授权、文件选择器等）
4. **USB 连接依赖**：当前基于 USB ADB 连接，WiFi ADB 可解决但延迟更高
5. **跨端框架不确定性**：若最终采用 Flutter 需切换为 Appium Flutter Driver，当前 UiAutomator2 无法识别 Flutter 元素树

#### 与备选方案对比

| 维度 | 当前方案 (Appium + Pytest) | Chrome Remote Debugging | 云真机平台 |
|------|--------------------------|------------------------|-----------|
| 自动化能力 | ✅ 完全自动化 | ❌ 纯手动 | ✅ 自动化 |
| 环境搭建 | 中等（需安装 Appium/ChromeDriver） | 简单（仅需 Chrome） | 简单（开箱即用） |
| 测试报告 | ✅ Allure 可视化 | ❌ 无 | 平台自带 |
| 真机覆盖 | 有限（自有设备） | 有限 | 广泛 |
| 成本 | 免费 | 免费 | 按量付费 |
| 自定义扩展 | ✅ 完全可控 | ❌ 不支持 | 受限 |
| CI/CD 集成 | ✅ 原生支持 | ❌ 不支持 | 平台提供 |

## 三、测试环境

### 3.1 硬件环境

| 角色 | 配置 | 说明 |
|------|------|------|
| 测试 PC | Windows 10/11, 8GB+ RAM | 运行 Appium + Pytest |
| 测试手机 | 24117RK2CC, Android 16, 1440×3200 | 主要测试设备 |
| USB 数据线 | 支持数据传输 | 连接 PC 与手机 |

### 3.2 软件环境

| 软件 | 安装方式 | 验证命令 |
|------|---------|---------|
| Python 3.13 | `python -m venv .venv` | `python --version` |
| Node.js 24 | 官网安装 | `node --version` |
| Appium 3.6 | `npm install -g appium` | `appium --version` |
| UiAutomator2 Driver | `appium driver install uiautomator2` | `appium driver list --installed` |
| ChromeDriver | 手动下载到 `~/.appium/chromedriver/` | Appium 启动时自动检测 |
| ADB | 项目内置 `platform-tools/` | `adb version` |
| Python 依赖 | `pip install -r requirements.txt` | `python setup_check.py` |

### 3.3 手机端配置

1. **开启开发者模式**：设置 → 关于手机 → 连续点击版本号 7 次
2. **开启 USB 调试**：设置 → 开发人员选项 → USB 调试
3. **安装 Chrome**：Google Play Store → Google Chrome
4. **连接 PC**：USB 数据线连接，手机上确认"允许 USB 调试"

### 3.4 环境变量

| 变量 | 值 | 设置方式 |
|------|-----|---------|
| `ANDROID_HOME` | `D:\liyang\code\Android_Auto_Test` | Win+R → sysdm.cpl → 环境变量 |

## 六、测试报告

### 6.1 Allure 报告内容

每次测试执行后自动生成，包含：

- **执行概览**：通过/失败/跳过数量，耗时统计
- **测试趋势**：历史执行对比（CI 模式下）
- **用例详情**：按 Epic → Feature → Story 层级展示
- **步骤记录**：每个 `@allure.step` 的执行耗时
- **失败附件**：失败截图 (PNG)、页面源码 (XML/HTML)、执行日志
- **环境信息**：设备型号、Android 版本、Chrome 版本、测试环境

### 6.2 报告生成命令

```bash
# 运行测试并输出 Allure 数据
pytest tests/ -v --alluredir=reports/allure-results

# 生成 HTML 报告并打开
allure serve reports/allure-results

# 生成静态报告
allure generate reports/allure-results -o reports/allure-report --clean
```

## 七、CI/CD 集成方案（规划）

```
Git Push ──► Jenkins / GitLab CI
                │
                ├──► 1. 拉取代码
                ├──► 2. 安装依赖 (pip install + npm install)
                ├──► 3. 启动 Appium Server (后台)
                ├──► 4. 运行测试 (pytest --alluredir=...)
                ├──► 5. 生成 Allure 报告
                └──► 6. 归档报告 + 通知结果
```

### 建议配置

- **触发条件**：每日凌晨 + MR 提交
- **超时设置**：30 分钟
- **失败策略**：重试 2 次后标记失败
- **报告保留**：最近 30 次执行记录

## 八、已知问题与限制

| 问题 | 影响 | 状态 |
|------|------|------|
| 手机未装 Chrome | 浏览器模式不可用 | 已解决（安装 Chrome 150） |
| Chrome 版本过新 | 需手动下载匹配 ChromeDriver | 已解决 |
| ANDROID_HOME 未设置 | Appium 无法启动 Session | 已解决（系统环境变量 + 代码自动检测） |
| 设备 platformVersion 不匹配 | 配置写死版本号 | 已解决（代码自动检测修正） |
| Android 14+ hidden_api_policy | Appium 启动 Session 权限报错 | 已解决（--relaxed-security） |
| 无正式 APK | 原生 APP 测试暂不可用 | 待 APK 就绪 |
| 跨端框架未定 | 可能影响元素定位方式 | 待研发确认 |
